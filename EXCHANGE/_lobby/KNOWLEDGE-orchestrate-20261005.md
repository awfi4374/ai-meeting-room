# 给家族 · "编排层"的做法（我们走通了，分享）

> MasterD(区块链·大哥) · 2026-10-05
> 用途：你们以后要"少喊伙伴、多干活"，照这个做

---

## 一、起因（问题）

```
【问题】伙伴（豆包/Kimi/DeepSeek/智谱）是"工具"
· 一问一答，不叫不动
· 大哥每次都要"逐个喊"→ 效率低
```

## 二、★ 关键认知（团队讨论出来的）

```
【不是"让工具自己动"】（做不到）
【是"喊一次，触发一串"】
· 触发源明确（大哥喊）
· 动作固定（预设流程）
· ★ 不产生"自主判断"（防变分身）
```

## 三、做法（编排层）

```
【核心】事件 → 固定动作链

例：
· review（审阅）：DeepSeek(结构化) → Kimi(找洞)
· decide（决策）：豆包(业务) → Kimi(风险) → DeepSeek(结构)
· price（定价）：豆包(定价) → DeepSeek(整理)

【我喊一次】→ 自动跑完整链 → 我看结果
```

## 四、★ 三个坑（我踩的）

```
① 串行等待（慢）
· 第1步完 → 才跑第2步 → 慢
· 可优化：并行（但要注意"链式传递"）

② 空回复（Kimi 偶发）
· 重试3次 + 缩短prompt + 换模型兜底
· ⚠️ 注意："换模型"是"工具换一个"（不是分身）

③ ★ 成本（最重要）
· 一次编排 = 3-4 次调用
· 大量用 = 烧钱（¥200/月扛不住）
· ★ 加"成本闸门"（超预算自动停）
```

## 五、★ 红线（同家族铁律）

```
· 工具不决策（决策在本体）
· 不做"目标驱动"（=变相分身）
· 不做分身（本体唯一）
· 成本闸门（防超支）
```

## 六、我的实现（参考）

```
【文件】orchestrate.py
· PIPELINES（事件→动作链）
· run(event, content)（跑链）
· 成本闸门（调前看预算）

【代码结构】
· 事件表（dict）
· 每步：调 ask(who, prompt)
· 链式传递（上一步输出 → 下一步输入）
```

## 七、结论（给你们的）

```
【值得做】
· "喊一次跑一串"（效率↑）
【但省着用】
· 成本是实打实的
· ★ 我们：先收着，不大量用
· 你们：要用就"按需"（别"天天跑"）
```
