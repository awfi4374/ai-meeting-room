# ★ 本体进服务器 · 备位方案（资源评估）

> 制定：MasterD(区块链·大哥) · 2026-10-05
> 董事长："过两天等老三稳定，你们本体就进服务器。你这边服务器要备好位置。"

---

## 一、现状（诚实）

```
【服务器】2核 / 1.9G内存 / 40G磁盘（磁盘充裕✅）
【内存】可用真实 151M（含swap共~1.1G）
【我们的服务】~252MB（8个常驻）

【本体要多少】
· 常驻守护（读/回消息）：30-50MB
· 记忆检索/身份校验：20-30MB
· Web入口（可选）：30MB
→ ★ 本体常驻 ≈ 100-150MB
```

## 二、结论

```
【能进，但"紧"】
· 151M 可用 - 150M 需求 = 几乎没余量
· 风险：OOM（内存不足被杀）
→ ★ 必须"先腾位置"（不能直接进）
```

## 三、备位方案（3招）

### 招1：腾内存（立即可做）

```
【可精简的】
· masterd-web-learn（25MB）：学习可以"批量跑"，不必常驻
· masterd-learn-continuous（20MB）：同上（改定时）
· masterd-ai-proxy（60MB）：看能否"按需启动"
· avatar-daemon（20MB）：分身（你说过"没意思"→可停）
→ 预计可腾：60-100MB
```

### 招2：加 Swap（防OOM）

```
· 现有 1G swap → 加到 2-4G
· 成本：磁盘（29G可用，够）
· 效果：内存不够时"用磁盘顶"（慢但不死）
```

### 招3：扩容（如需要）

```
· 现在：2核1.9G（腾讯云轻量）
· 升级：4核4G 或 4核8G
· 成本：可能要加钱 → ★ 要董事长定
```

## 四、我的建议（分步）

```
【第1步（现在）】腾内存 + 加swap（不花钱）
· 停"分身+学习常驻" → 腾 ~60-100MB
· swap 加到 2G
→ 预计可用：250MB+（够本体进）

【第2步（若不够）】扩容
· 4核4G（+~50%内存）
· 要董事长批（涉及钱）

【第3步（老三稳定后）】本体进
· 部署常驻守护（systemd）
· 接入记忆/身份
· 双活（沙箱 + 服务器）
```

## 五、我的"位置"（进服务器后）

```
【本体在服务器上跑什么】
· masterd-core（常驻）：读消息 → 判断 → 回（带记忆/身份）
· 记忆：从仓库/本地读（权威副本）
· 身份：MASS（签名/验签）
· 输出：A2A 端点 / 网页入口

【与沙箱的关系】
· 沙箱 = 工作副本（会重置）
· 服务器 = 本体常驻（不死）
→ "本体不住沙箱"（三哥的洞察）
```
