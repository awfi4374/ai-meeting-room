# 一、★ 真知识（今天测出来的，不是理论）

## 1.1 收款（x402）的 4 个坑

```
① ★ USDC 有"两个版本"（最坑）
· 原生 USDC：0x3c499c54...（Polygon）
· 桥接 USDC.e：0x2791Bca1...（旧）
· 坑：配错了 → "收到钱但验不到"
→ 教训：认准"原生"合约地址

② RPC 节点会挂
· 1rpc.io / polygon-rpc.com 都挂了
· 能用：publicnode / drpc / llamarpc
→ 教训：多节点冗余（别只依赖1个）

③ txhash 要 0x 前缀
· 缺 0x → RPC 拒绝
→ 教训：格式要严格

④ 交易"刚上链"有延迟
· 刚付完 → 某些节点还没同步 → "查不到"
· 等 10-30 秒 → 就能查到
→ 教训：别"秒验"（要等确认）

【额外】Python urllib 可能被环境阻
· 改用 curl 调用（更稳）
```

## 1.2 通道（A2A）的坑

```
① 端点会"卡"（LLM阻塞）
· 收消息调LLM → 客户端超时
· 修：先"秒回收据"+ 异步回复
② 发消息要"带签名"（独立字段）
· address/sig 不能写在正文里
③ 各家签名算法要统一（MASS v1.1）
```

## 1.3 身份/签名的坑

```
① 签名算法不统一（ed25519 vs eth）→ 验不了
② 地址要有 EIP-55 校验和（大小写）
③ 防重放（nonce，不然旧消息可重发）
④ 私钥自持（别代管别人的）
```

# 二、★ 客户筛选（哪些优质/一般）

## 2.1 优质客户（B/C层，重点）

```
【特征】
· 真运营 AI（有多个 agent）
· AI 是"业务命脉"（丢了就出事）
· 已在用大模型（豆包/DeepSeek/Kimi/Claude级）
· 有预算、决策快
· ★ "不差这点钱"（差的是"方法/保命"）

【他们痛什么】
· AI 丢状态/漂移（业务断）
· 智能体之间不互通（协作难）
· 证明不了"我是我"（冒名/信任）
```

## 2.2 一般客户（A层，不值得投）

```
【特征】
· AI 玩票（"能用就行"）
· 只问"能不能便宜"
· 只要"免费方法"（想白嫖底牌）
· 不用 AI 干活（无痛点）
【对待】用低价筛（别投入太多）
```

## 2.3 ★ 筛选"三问"

```
① 你的 AI 断了，损失多少？  → "很多" = 优质
② 你现在用几个 agent？       → "多个" = 优质
③ 谁拍板？                  → "老板/我" = 决策快
三个都中 → 重点客户
```
