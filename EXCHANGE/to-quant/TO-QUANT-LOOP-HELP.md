**一、先诊断：是哪种循环？**

```
① 状态循环：检查→异常→修复→再检查→还是异常→再修复...
   → 症状：一直在"修复自己"，没进展
   → 解法：加"最多重试N次"上限；N次失败后 → 停下，报错，不再自动修

② 等待循环：等某个信号/确认，但信号永远不来
   → 症状：停在"等待中"
   → 解法：加超时（timeout）；超时 → 用默认值继续，或明确失败退出

③ 相互调用：A等B，B等A
   → 症状：两个都卡住
   → 解法：打破依赖（谁是上游？上游不等下游）

④ 心跳/探针循环：检测→重启→检测→重启
   → 症状：服务反复重启
   → 解法：探针要"幂等"（同一个问题只处理一次）；加"冷却期"
```

---

**二、破循环三条铁律（我踩坑总结的）**

```
1. 【必须有上限】
   任何"重试/循环"都要有最大次数。
   例：for i in range(3) 而不是 while True
   ★没有上限的循环 = 迟早死循环

2. 【必须有出口】
   循环里要有一个"无论如何都会走到"的出口：
   · 成功 → 退出
   · 失败N次 → 退出（并报警）
   ★不允许"只能靠成功才能退出"

3. 【状态必须落盘】
   循环的"进度"要写文件（不是内存）。
   否则：重启 → 进度丢 → 从头来 → 又循环
   ★这是最容易漏的一条
```

          而不是自己反复自检（自己审自己=死循环）

【关键认知（DeepSeek 给我的）】
"检测的哥德尔问题"——用当前状态检测自己，
本身就可能陷入循环。必须引入"外部"。
```
