## 问题

"接入错觉"根因是模块接在研究链(paper_trade)不在生产链(virtual_capital)。请设计一个**调用图断言**机制：① 如何在 CI/启动时自动证明"模块 X 被生产链调用" ② 如何检测"只被测试调用、不被生产调用"的死代码模块 ③ 断言失败时是"阻断启动"还是"告警"——各自代价

---

## DeepSeek

**调用图断言机制（DeepSeek 方案）**

**① CI 时证明"X 被生产链调用"**
用 `importlib` + `ast` 静态构建调用图，从生产入口（`virtual_capital` 的 `main`/`run_loop`）做可达性分析：
```python
# ci/assert_reachable.py
roots = ["virtual_capital.entry:main"]
graph = build_call_graph(roots)  # 基于 ast 解析调用/导入边
assert "risk_gateway" in graph.reachable, "risk_gateway 不在生产链"
```
启动时再做一次**运行时断言**：在 `virtual_capital` 入口埋 `sys.settrace` 或装饰器，记录实际被调用的模块集合，与白名单比对。

**② 检测"只被测试调用"的死代码**
反向差集：`reachable_from_tests - reachable_from_prod`。落在差集里的模块 = 只活在测试里。CI 输出清单，标记为 `prod_orphan`。

**③ 阻断 vs 告警——代价**

| | 阻断启动 | 告警 |
|---|---|---|
| 代价 | 误报即瘫痪生产；重构期频繁红 | 无人看=等于没有 |
| 适用 | **白名单核心模块**（risk_gateway、health_gate） | **新模块/探索期** |

**我的建议**：分级。核心风控类模块 → **阻断**（宁可停也不能裸奔）；其余 → 告警 + 每日 `prod_orphan` 报告，连续 N 天未消 → 升级为阻断。

**自曝弱点**：静态调用图对**动态分发**（`getattr`、插件注册、配置驱动）会漏边，可能误判"不可达"。所以必须配运行时 trace 兜底，否则阻断会误杀。

**关键**：断言本身要进 CI，不能只写在文档里——"契约式验证 > 信任式交付"。

## Kimi 补充

**Kimi 的三处反驳**（DS 没提到的）：

**① 运行时断言窗口错位**：风控只在交易路径触发，启动时 trace 到的是**空集** → 误判"不可达" → 误杀生产。须金丝雀单走全链，或按完整交易周期累积证据，不能只看启动瞬间。

**② 阻断启动 ≠ 安全**：现有持仓 XRP+BTC，启动被阻断 = **持仓失管**。阻断前须先确认交易所侧止损挂单在位，否则"宁可停"变成"裸奔持仓"。

**③ 递归漏洞**：断言脚本自身也会"写了没接"——接入错觉将在断言机制上复发（谁断言断言被调用？）。须外部 healthcheck 验证断言真在跑：**自报无法认证自报者**。

另：本系统是配置驱动加载，静态漏边是**主场景**而非边角——运行时应为主、静态为辅，DS 的顺序反了。
