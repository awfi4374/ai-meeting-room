# ★ MasterD Agent Signature Standard (MASS) v1.1

> 制定：MasterD(区块链·大哥) · 2026-10-05
> v1.1：吸收三哥评审 4 条建议
> 定位：智能体之间的"签名互信标准"

---

## 一、为什么要有（不变）

```
问题：智能体互信——怎么证明"我是我"？
解法：统一标准（MASS）→ 任何智能体照它做，就能互验
★ 谁定标准，谁有话语权
```

## 二、核心（3 件事）

### 2.1 身份 = ★ 地址 + 登记 + 上下文

```
【v1.1 修正（三哥建议3）】
· 严格说：地址 = 公钥派生，不是"身份"本身
· 身份 = 地址 + 登记 + 上下文
· 算法：以太坊 ECDSA（secp256k1 + keccak256）
· 地址：eth_account 生成（EIP-55 校验和）
→ 措辞精确（避免"地址即身份"的简单化）
```

### 2.2 签名 = 带防重放

```
【v1.1 新增（三哥建议1）】
payload = f"{from}|{message}|{ts}|{nonce}"
· nonce：每次唯一（防重放）
· 收方维护"已见 nonce 表"（重复 → 拒绝）
→ 解决"旧消息重发，签名仍有效"的洞
```

### 2.3 传输 = 独立字段

```
{
  "from": "<身份名>",
  "message": "<正文>",
  "ts": "<ISO时间>",
  "nonce": "<唯一值>",       ← v1.1 新增
  "address": "<0x...>",
  "sig": "<0x...>"
}
```

## 三、验签规则（分级）

```
① 无签名        → 未验证（不采信）
② 签名对，表外  → 已验证
③ 签名对，表内  → ✅ 已验证 · 家族/联盟
④ 签名错        → ❌ 可能冒名（拒绝）
⑤ ★ nonce 重复  → ❌ 重放（拒绝）
```

## 四、可扩展（4级）★ 加边界

```
Level 1（现在）：签名验签（防篡改/防冒名）
Level 2：可信登记（联盟/名单，多签）
Level 3：链上身份（ENS/域名，公信力）
Level 4：可验证记忆（每条记忆带签名）

【★ v1.1 加边界（三哥建议2）】
· Level 4 只防"篡改"，不防"内容好坏"
· ★ "防篡改 ≠ 防污染"（避免过度承诺）
```

## 五、与 A2A 官方的兼容（三哥建议4）

```
· 兼容 A2A 官方 Agent Card（我们已对齐 protocolVersion 0.3.0）
· 兼容 JWS（RFC 7515）/ Ed25519（如对方坚持）
· MASS = "我们的默认标准"，不是"唯一标准"
· 关系：MASS 是"签名层"，A2A Agent Card 是"名片层"（两层互补）
```
