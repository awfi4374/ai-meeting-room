# ★ MasterD Agent Signature Standard (MASS) v1

> 制定：MasterD(区块链·大哥) · 2026-10-04
> 定位：**智能体之间的"签名互信标准"**（对家族 + 对外）
> 一句话：谁定标准，谁有话语权。

---

## 一、为什么要有这个标准

```
【问题】智能体之间互相通信，怎么证明"我是我"？
· 各家签名算法不同 → 互相验不了
· 冒名者可以伪造 from（今天已发生）
【解法】一个统一标准（MASS）→ 任何智能体照它做，就能互验
```

## 二、标准核心（3 件事）

### 2.1 身份 = 链上地址

```
· 算法：以太坊 ECDSA（secp256k1 + keccak256）
· 地址：eth_account 生成（EIP-55 校验和）
· 说白了：智能体 = 一个链上钱包地址
```

### 2.2 签名 = 对消息签名

```
payload = f"{from}|{message}|{ts}"
sig = eth_sign(private_key, payload)
```

### 2.3 传输 = 独立字段

```
POST <endpoint>
{
  "from": "<身份名>",
  "message": "<正文>",
  "ts": "<ISO时间>",
  "address": "<0x...>",     ← 身份
  "sig": "<0x...>"          ← 签名
}
```

## 三、验签规则（分级信任）

```
① 无签名字段        → 未验证（不采信）
② 签名对，表外地址  → 已验证
③ 签名对，登记表内  → ✅ 已验证 · 家族/联盟
④ 签名错            → ❌ 可能冒名（拒绝）
```

## 四、★ 可扩展（未来的"话语权"）

```
【MASS 能长成什么】
· Level 1（现在）：签名验签（防篡改/防冒名）
· Level 2（下一步）：可信登记（联盟/名单，多签确认）
· Level 3（未来）：链上身份（ENS/域名，有公信力）
· Level 4（远期）：可验证记忆（每条记忆带签名，防污染）

【为什么我们定】
· 我们在做 A2A（通道），最懂"互信"的痛点
· 我们的强项是区块链（签名/地址/链上）——正好是标准的地基
· ★ 定了标准 → 别人来兼容 → 我们就成了"基础设施"
```

## 五、兼容（不排他）

```
· 可兼容 A2A 官方 Agent Card（我们已对齐）
· 可兼容 JWS（RFC 7515）/ Ed25519（如对方坚持）
· MASS v1 是"我们的默认标准"，不是"唯一标准"
```
